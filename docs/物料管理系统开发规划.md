## 1. 项目概述

### 1.1 背景
作为嵌入式硬件爱好者，随着元器件种类和数量增多，手工管理库存越来越困难，经常出现“找不到某个电阻”“重复购买已有芯片”等问题。本项目旨在提供一个轻量级、易用的 B/S 架构物料管理系统，解决个人或小团队的物料管理痛点。

### 1.2 目标

- 提供元器件信息的集中存储与快速检索（按名称、值、封装、品牌、分类等）。
- 实现入库、出库及批量出库操作，自动更新库存。
- 支持 BOM 导入与 BOM 管理，便于按项目成清单出库。
- 支持低库存预警，避免生产中断。
- 记录库存变动流水，便于追溯。
- 提供采购 / 消耗统计分析与导出。
- 权限区分管理员与普通用户。

### 1.3 非功能性需求

- 响应速度：本地局域网下页面加载 < 2 秒，API 响应 < 500ms。
- 数据可靠性：SQLite 单文件，备份即复制文件，交易使用事务保证一致性。
- 可扩展性：后端分层、前端组件化，便于后续扩展。

## 2. 需求分析

### 2.1 用户角色

| 角色 | 权限说明 |
|------|----------|
| 管理员 | 全部权限：增删改查物料、分类、供应商、库位、BOM、用户，查看所有流水与统计 |
| 普通用户 | 查询物料、分类/供应商/库位，进行入库 / 出库 / 批量出库，查看流水与统计 |

> 说明：物料、分类、供应商、库位、BOM、用户的「写」操作要求管理员权限；入库 / 出库 / 批量出库等库存操作对已登录用户开放。

### 2.2 功能需求（已实现）

- **物料管理**：分页查询、多条件搜索、新增 / 编辑 / 删除，关联分类、值、封装、品牌、Datasheet、最低库存、库位、供应商、单位等。
- **分类管理**：树形多级分类，可增删改、搜索。
- **供应商管理**：供应商信息 CRUD。
- **库位管理**：库位编号 CRUD。
- **入库操作**：选择物料、数量、可选单价、备注，过账后增加库存。
- **出库操作**：选择物料、数量、备注，过账前校验库存。
- **批量出库**：选择 BOM 整单批量出库，表格内可增删行、修改数量。
- **BOM 导入**：上传 EDA 导出的 CSV 物料清单，匹配库存、标出缺口，并可一键创建缺失物料。
- **BOM 管理**：维护常用 BOM（物料 + 数量）。
- **库存查询 / 流水**：按物料、类型、时间段过滤流水。
- **低库存预警**：展示当前库存 ≤ 最低库存的物料。
- **统计分析**：采购 / 消耗概览、月度趋势、Top 组件、供应商与分类金额分布、库存估值，支持时间范围筛选与导出 CSV。
- **用户登录 / 登出**：JWT 认证。

## 4. 系统架构设计

本项目采用**前后端分离**架构，前端通过 HTTP 调用后端 RESTful API，后端通过 SQLAlchemy ORM 访问 SQLite。

### 4.1 开发环境拓扑

```
+--------------+     HTTP      +------------------+   /api 代理   +-----------------+
|  浏览器      | ------------> | Vite 开发服务器  | ------------> | Flask (5000)     |
| (Vue 3 SPA)  |               | (5173)           |               | RESTful API      |
+--------------+               +------------------+               +--------+--------+
                                                                          |
                                                                          v
                                                                +-----------------+
                                                                | SQLite 3         |
                                                                | backend/instance |
                                                                +-----------------+
```

### 4.2 生产部署拓扑（可选）

```
浏览器 → Nginx（静态资源 + 反向代理 /api）→ Gunicorn + Flask → SQLite
```

### 4.3 后端分层

实际代码目录与职责：

- `routes/`：控制器层，定义 API 路由、解析参数、返回统一 JSON。
- `services/`：业务逻辑层，如库存过账、批量出库、BOM 解析、统计分析。
- `models/`：SQLAlchemy ORM 模型（数据访问）。
- `utils/`：通用工具（JWT 生成与校验、密码哈希、鉴权装饰器）。
- `config/`：配置（读取 `.env`，含数据库地址、密钥、管理员初始账号）。

### 4.4 统一返回格式

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

HTTP 状态码与业务 `code` 语义一致；错误时 `message` 提供中文提示。

## 5. 数据库设计

> 表结构由 SQLAlchemy 模型映射生成。SQLite 中 `INTEGER PRIMARY KEY` 自增；`Enum` 映射为带约束的文本列；金额字段使用 `FLOAT`（个人场景足够，如需严格货币精度可改为 `NUMERIC`）。

### 5.1 ER 关系

```
users      (1) ----< (N) transactions
categories (1) ----< (N) components
suppliers  (1) ----< (N) components
locations  (1) ----< (N) components
components (1) ----< (N) transactions
components (1) ----< (N) bom_items
boms       (1) ----< (N) bom_items
```

### 5.2 表结构

#### 5.2.1 用户表 `users`

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY | 用户 ID |
| username | VARCHAR(50) | UNIQUE, NOT NULL | 登录名 |
| password_hash | VARCHAR(128) | NOT NULL | 密码哈希（Werkzeug） |
| role | ENUM('admin','user') | DEFAULT 'user' | 角色 |
| email | VARCHAR(100) | | 邮箱 |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |

#### 5.2.2 分类表 `categories`

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY | 分类 ID |
| name | VARCHAR(50) | NOT NULL | 分类名称 |
| parent_id | INTEGER | DEFAULT NULL | 父级 ID（自关联，支持多级） |

#### 5.2.3 供应商表 `suppliers`

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY | 供应商 ID |
| name | VARCHAR(100) | NOT NULL, UNIQUE | 供应商名称 |
| contact | VARCHAR(50) | | 联系人 |
| phone | VARCHAR(20) | | 电话 |
| address | VARCHAR(200) | | 地址 |
| website | VARCHAR(200) | | 官网 |

#### 5.2.4 库位表 `locations`

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY | 库位 ID |
| name | VARCHAR(50) | NOT NULL, UNIQUE | 库位编号（如 A1-2） |
| description | VARCHAR(100) | | 补充描述 |

#### 5.2.5 物料表 `components`（核心）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY | 物料 ID |
| category_id | INTEGER | FK(categories.id) | 分类 |
| name | VARCHAR(100) | NOT NULL | 名称 |
| value | VARCHAR(50) | | 值（如 10kΩ） |
| package | VARCHAR(30) | | 封装（如 0805） |
| tolerance | VARCHAR(10) | | 精度 |
| brand | VARCHAR(50) | | 品牌 |
| datasheet_url | VARCHAR(255) | | 数据手册链接 |
| min_stock | INTEGER | DEFAULT 0 | 最低库存阈值 |
| current_stock | INTEGER | DEFAULT 0 | 当前库存（非负） |
| location_id | INTEGER | FK(locations.id) | 库位 |
| supplier_id | INTEGER | FK(suppliers.id) | 主要供应商 |
| unit | VARCHAR(10) | DEFAULT '个' | 单位 |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |

#### 5.2.6 库存流水表 `transactions`

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY | 流水 ID |
| component_id | INTEGER | FK(components.id), NOT NULL | 物料 |
| type | ENUM('in','out') | NOT NULL | 入库 / 出库 |
| quantity | INTEGER | NOT NULL | 变动数量（正整数） |
| unit_price | FLOAT | | 入库单价（元），出库为空 |
| order_id | INTEGER | | 关联单号（预留） |
| operator_id | INTEGER | FK(users.id) | 操作人 |
| note | VARCHAR(255) | | 备注 |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 操作时间 |

#### 5.2.7 BOM 表 `boms`

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY | BOM ID |
| name | VARCHAR(100) | NOT NULL | BOM 名称 |
| description | VARCHAR(255) | | 说明 |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |

#### 5.2.8 BOM 明细表 `bom_items`

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY | 明细 ID |
| bom_id | INTEGER | FK(boms.id), NOT NULL | 所属 BOM |
| component_id | INTEGER | FK(components.id), NOT NULL | 物料 |
| quantity | INTEGER | NOT NULL, DEFAULT 1 | 数量 |

### 5.3 索引与约束建议

- `components(name/value/package)`、`transactions(component_id/created_at)` 适合建立索引（数据量大时）。
- 删除分类 / 供应商 / 库位时，应用层校验是否仍被物料引用；删除 BOM 时级联删除明细。
- 库存扣减在服务层使用 SQLAlchemy 事务，保证“扣库存 + 写流水”原子性。

## 6. 后端 API 接口设计

所有接口统一前缀 `/api`，鉴权通过 `Authorization: Bearer <token>`。

### 6.1 认证

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| POST | /api/auth/login | 公开 | 登录，返回 JWT |
| GET | /api/auth/me | 已登录 | 当前用户信息 |
| POST | /api/auth/logout | 公开 | 登出（前端丢弃 token） |

### 6.2 物料

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | /api/components | 已登录 | 分页查询（keyword、category_id） |
| POST | /api/components | 管理员 | 新增物料 |
| GET | /api/components/low-stock | 已登录 | 低库存列表 |
| GET | /api/components/{id} | 已登录 | 物料详情 |
| PUT | /api/components/{id} | 管理员 | 更新物料 |
| DELETE | /api/components/{id} | 管理员 | 删除物料 |

### 6.3 分类 / 供应商 / 库位

三者均为标准 CRUD，前缀分别为 `/api/categories`、`/api/suppliers`、`/api/locations`：

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | /api/{resource} | 已登录 | 列表 |
| POST | /api/{resource} | 管理员 | 新增 |
| PUT | /api/{resource}/{id} | 管理员 | 更新 |
| DELETE | /api/{resource}/{id} | 管理员 | 删除 |

### 6.4 出入库

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| POST | /api/transactions/in | 已登录 | 入库（支持可选 unit_price） |
| POST | /api/transactions/out | 已登录 | 出库（校验库存） |
| POST | /api/transactions/out-batch | 已登录 | 按明细批量出库 |
| GET | /api/transactions | 已登录 | 流水（按物料、类型、时间过滤） |

### 6.5 用户管理

| 方法 | 路径 | 权限 | 说明 |

### 6.6 BOM 导入与 BOM 管理

## 8. 开发环境搭建

### 8.1 后端

```bash
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate   macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env   # macOS/Linux: cp .env.example .env
```

```bash
cd frontend
```

前端默认 `http://localhost:5173`，Vite 已把 `/api` 代理到后端。

## 11. 部署与运维

### 11.1 数据备份

所有数据位于单文件：

```
backend/instance/app.db
```

备份 = 复制该文件；恢复 = 用备份文件覆盖后重启。建议停止后端后复制，或使用 SQLite 在线备份。

### 11.2 生产部署（可选）

个人 / 局域网使用可直接跑 Flask + Vite；如需对外提供 HTTPS 或更高性能，推荐：

1. 前端 `npm run build` 生成 `dist/`，由 Nginx 托管并反向代理 `/api`。
2. 后端用 Gunicorn 运行：`gunicorn -w 2 -b 127.0.0.1:5000 app:app`。
3. 配置 HTTPS（如 Let's Encrypt）。

## 12. 安全与最佳实践

- **环境变量**：数据库地址、`SECRET_KEY`、初始管理员账号密码均放在 `backend/.env`，该文件已被 `.gitignore` 排除，**不提交**。
- **密钥**：正式使用前把 `SECRET_KEY` 改为随机字符串；不要复用示例值。
- **默认账号**：首次登录后及时修改管理员密码或另建账号；不要长期使用默认密码。
- **密码存储**：使用 Werkzeug 哈希（不可逆），不存储明文。
- **权限**：写操作统一由 `admin_required` 装饰器保护；库存操作由 `login_required` 保护。
- **SQLite 外键**：如需更严格的外键约束，可在连接建立时执行 `PRAGMA foreign_keys=ON`。
