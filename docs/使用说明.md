# PartKeeper 使用说明

面向个人 / 小团队电子 DIY 场景的轻量级物料管理系统。本文档介绍如何安装启动、使用各功能，以及数据与安全注意事项。

## 1. 环境要求

- Python 3.10+（后端）
- Node.js 18+（前端，仅开发/构建需要）
- 数据库：SQLite（内置，无需安装）

## 2. 安装与启动

### 2.1 后端

```bash
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate   macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env    # macOS/Linux: cp .env.example .env
python app.py
```

后端默认地址 `http://localhost:5000`。启动时自动：

- 创建 SQLite 数据库文件（位于 `backend/instance/app.db`）
- 建表并执行轻量迁移
- 补充常用元器件分类（无源器件、集成电路、PCB、连接器、结构件、零件、电机等）
- 创建初始管理员账号

### 2.2 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认地址 `http://localhost:5173`，已把 `/api` 请求代理到后端 5000 端口。

> Windows 下也可以直接运行仓库根目录的 `start_servers.ps1`（同时启动前后端），用 `start_backend.ps1` 只启动后端。

## 3. 账号与安全

- 初始管理员默认 `admin / admin123`（可通过 `backend/.env` 的 `ADMIN_USERNAME`、`ADMIN_PASSWORD` 修改）。
- 首次登录后建议进入「用户管理」修改管理员密码，或创建自己的账号。
- `backend/.env` 已被 `.gitignore` 排除，**不会提交到仓库**；`backend/.env.example` 只是模板，不含真实密钥。
- 正式使用前请把 `.env` 中的 `SECRET_KEY` 改成随机字符串。

## 4. 功能使用

### 4.1 仪表盘
展示物料总数、低库存数、累计采购金额、累计消耗数量、当前库存估值、流水记录数，以及最近流水。

### 4.2 物料管理
- 顶部可按关键字、分类搜索；支持分页。
- 「新增物料」填写名称、值、封装、精度、品牌、单位、分类、库位、供应商、最低库存、当前库存、Datasheet 链接。
- 「BOM 导入」：上传 EDA 导出的 CSV 物料清单（需含“值/Value”列），系统会与现有库存匹配并标出缺口；「创建缺失物料」可把缺失项一键建成物料（最低库存=数量，便于补货）。

### 4.3 分类管理
树形多级分类，可新增根分类 / 子分类、改名、删除；支持按名称搜索。已预置常用分类。

### 4.4 供应商 / 库位管理
维护供应商信息（名称、联系人、电话、地址、官网）和库位编号（如 A1-2），均为表格 CRUD。

### 4.5 BOM 管理
维护常用物料清单：新建 BOM、填写名称/说明、搜索物料并添加、修改数量、移除行。出库时可复用。

### 4.6 入库操作
选择物料、填写数量、备注，入库时可选填「单价」用于采购金额统计。

### 4.7 出库操作
- 单物料出库：选择物料、填写数量，系统校验库存是否充足。
- 「按 BOM 批量出库」：选择 BOM 自动载入物料清单，表格内可增删行、修改数量，确认后一次性批量出库；任一行库存不足会整体回滚并提示。

### 4.8 库存流水
按物料、操作类型（入库/出库）、时间段过滤所有库存变动记录。

### 4.9 低库存预警
展示当前库存 ≤ 最低库存的物料，可跳转去入库补货。

### 4.10 统计分析
- 采购 / 消耗概览、库存估值。
- 月度采购/消耗趋势、采购金额 Top 组件、消耗数量 Top 组件、供应商与分类金额分布。
- 支持按时间范围筛选；「导出 CSV」按当前范围导出汇总。

### 4.11 用户管理（管理员）
创建用户、设置角色（管理员 / 普通用户）、重置密码、删除用户。

## 5. 数据备份与恢复

所有数据都在 SQLite 单文件中：

```
backend/instance/app.db
```

备份 = 复制该文件（建议在停止后端后复制，或使用 SQLite 的在线备份工具）。恢复 = 用备份文件覆盖同名文件后重启后端。

## 6. 常见问题

- **端口被占用**：修改 `backend/.env` 的 `APP_PORT`，并同步修改 `frontend/vite.config.js` 中的代理目标端口。
- **忘记管理员密码**：删除 `backend/instance/app.db` 后重启（会重置所有数据），或临时把 `ADMIN_PASSWORD` 改为新值并在「用户管理」中重置。
- **前端跨域/代理异常**：确认后端已启动在 5000 端口，前端开发服务器代理配置正确。
